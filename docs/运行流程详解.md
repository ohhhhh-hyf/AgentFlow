# `bootstrap.py --task minutes` 运行流程详解

> 命令：
>
> ```bash
> python bootstrap.py --task minutes --summary .\src\domain\meeting\samples\summary\meeting.txt --profile .\src\domain\meeting\samples\profile\object_profile.json --minutes_template .\src\domain\meeting\samples\summary_template\project_progress.md
> ```

本文按**进程启动 → 参数解析 → 输入读取 → 系统装配 → 图构建 → 图执行 → 流式输出 → 收尾**的顺序，逐步说明每一步在做什么、调用了哪些代码、发起了几次 LLM 请求。

---

## 0. 本命令的输入与预期输出

| 参数 | 值 | 含义 |
|---|---|---|
| `--task minutes` | `minutes` | 只生成**纪要**线（`minutes_generation`），不跑待办 |
| `--summary` | `meeting.txt` | 会议原文（验收会议转写稿） |
| `--profile` | `object_profile.json` | 客观画像：`perspective=objective` → 客观全员口径 |
| `--minutes_template` | `project_progress.md` | 纪要按"项目进度"Markdown 模板输出（`[描述]` 占位符被填充） |

预期输出：终端**逐块流式**打印一份按 `project_progress.md` 模板格式化的客观会议纪要，最后无质量警告。

## 1. Python 解释器启动与模块导入

```
python bootstrap.py ...
```

1. Python 启动，执行 `bootstrap.py` 模块代码（顶层到 `if __name__ == "__main__": main()`）。
2. **先执行模块顶层的 import**（bootstrap.py 第 1-19 行），按顺序加载：
   - 标准库：`argparse` / `asyncio` / `json` / `logging` / `os` / `sys` / `pathlib.Path`
   - `PROJECT_ROOT = Path(__file__).resolve().parent` → `D:\v4_stdio`
   - **`sys.path.insert(0, str(PROJECT_ROOT / "src"))`** —— 关键：把 `src/` 塞进模块搜索路径，后续 `from llm_client import ...` 等才能命中 `src/` 下的包
   - `from llm_client.config import load_env` → 触发加载 `src/llm_client/config.py`
   - `from domain.meeting import SAMPLES_DIR` → 触发加载 `src/domain/meeting/__init__.py`
   - `from domain.meeting.models import UserIdentity, is_objective_perspective` → 加载全部模型（含 `MeetingState`、契约生成区模型）
   - `from domain.meeting.orchestrator import MeetingAgentSystem, TASK_LINES` → 加载编排器（节点工厂、`_build_graph`、`run_streaming`、`TASK_LINES` 注册表）
3. import 期间，各模块的**模块级代码**执行：`orchestrator.py` 里定义 `TASK_LINES`、`_EMPTY_*`/`_REJECT_*` 常量、`LINE_CN_NAMES` 等。
4. 模块加载完毕，进入 `if __name__ == "__main__": main()`。

## 2. `main()`：环境变量预载 + 参数解析

```python
def main() -> None:
    load_env(PROJECT_ROOT / ".env")      # ① 先读 .env（让 MEETING_* 可作 parser 默认值）
    args = _parser().parse_args()        # ② 解析命令行
    try:
        asyncio.run(run(args.summary, args.profile, args.env,
                        args.minutes_template, args.item_template, args.tasks))
    except (...) as exc:
        raise SystemExit(f"错误：{exc}")
```

### 2.1 `load_env(PROJECT_ROOT / ".env")`

读取 `D:\v4_stdio\.env`，把其中 `KEY=VALUE` 行写入 `os.environ`（config.py 的 `load_env`）。本命令会用到的键：

```
DEEPSEEK_API_KEY=sk-xxx          # 必填，缺失则后续报错
DEEPSEEK_BASE_URL=https://api.deepseek.com   # 可选，有默认值
DEEPSEEK_MODEL=deepseek-chat     # 可选，有默认值
DEEPSEEK_TEMPERATURE=0           # 可选，有默认值
MEETING_SUMMARY / MEETING_PROFILE / MEETING_SUMMARY_TEMPLATE / MEETING_ITEM_TEMPLATE  # 路径兜底默认值
```

### 2.2 `parse_args()`：逐 token 扫描

argparse 从左到右消费 `sys.argv[1:]`（4 个参数组）：

| 命令行 token | 匹配的 add_argument | 结果 |
|---|---|---|
| `--task` | `--task`（`dest="tasks"`, `action="append"`） | `args.tasks = ["minutes"]` |
| `minutes` | 被消费为 `--task` 的值 | 同上 |
| `--summary` | `--summary/--summary-dir`（`type=Path`） | `args.summary = Path("...meeting.txt")` |
| `--profile` | `--profile/--profile-dir`（`type=Path`） | `args.profile = Path("...object_profile.json")` |
| `--minutes_template` | `--minutes_template/--summary_template`（`type=Path`） | `args.minutes_template = Path("...project_progress.md")` |

未传的项取默认：`args.item_template=None`、`args.env=Path(".env")`。

### 2.3 `asyncio.run(run(...))`

创建事件循环，执行异步入口 `run()`。**从此刻起进入 async 世界**，后续所有 LLM 调用都是协程。

## 3. `run()`：日志、输入读取、任务解析、模板读取

```python
async def run(summary, profile, env_file, minutes_template, item_template=None, tasks=None):
    setup_logging()                    # ① 配置 logging（控制台输出格式）
    load_env(_resolve_path(env_file))  # ② 再读一次 .env（幂等）
    transcript = _load_transcript(summary)   # ③
    user = _load_user(profile)               # ④
    line_names = _normalize_tasks(tasks, set(TASK_LINES))  # ⑤
    templates = {}                           # ⑥
    if minutes_template is not None:
        templates["minutes_generation"] = 模板文本
    ...
    system = MeetingAgentSystem()            # ⑦
    async for event in system.run_streaming(transcript, user, templates=templates, lines=line_names):
        ...  # ⑧ 消费事件打印
```

### 3.1 读取会议原文（`_load_transcript`）

- `_resolve_path("...\summary\meeting.txt")`：绝对路径直接命中。
- `_resolve_input_file(path, ".txt", "会议文本")`：确认是 `.txt` 文件 → `read_text(encoding="utf-8").strip()` → 非空校验。
- 结果：`transcript` = 完整会议转写稿字符串。

### 3.2 读取用户画像（`_load_user`）

- 读 `object_profile.json` → `json.loads` → `UserIdentity(**profile)`。
- 本命令画像关键字段：`"perspective": "objective"`、`"name": null`。
- `is_objective_perspective(user)` → **True**（客观模式），影响：
  - 视角模式标记 `objective_mode=True`
  - 终端标题显示"客观会议纪要"
  - `_shared_context`/`_supervisor_context` 里的视角说明为"客观全员口径"

### 3.3 任务名 → 线名（`_normalize_tasks`）

```python
TASK_ALIASES = {"minutes": "minutes_generation", "纪要": "minutes_generation",
                "actions": "action_items", "待办": "action_items"}
```

- `"minutes"` → 查表 → `"minutes_generation"`
- 校验：`"minutes_generation" in TASK_LINES` ✓
- 结果：`line_names = ["minutes_generation"]`（**只跑纪要线**）

### 3.4 读取纪要模板（`--minutes_template`）

- 读 `project_progress.md` 全文 → 非空校验 → `templates["minutes_generation"] = "<project_progress.md 全文>"`。
- 该模板包含 `# 项目信息`、`# 进度追踪`、`# 风险预警`、`# 后续计划`、`# 待办事项` 等 Markdown 结构与 `[...]` 占位符。

### 3.5 实例化系统（`MeetingAgentSystem()`）

```python
def __init__(self, client=None):
    self.client = client or LLMClient()          # ①
    agents = MeetingAgentFactory.create(self.client)  # ②
    self.meeting_understanding_agent = agents["meeting_understanding"]
    self.perspective_modeling_agent = agents["perspective_modeling"]
    self.minutes_generation_agent = agents["minutes_generation"]
    self.minutes_generation_supervisor = agents["minutes_generation_supervisor"]
    self.minutes_generation_render = agents["minutes_generation_render"]
    # 手写渲染/降级/Report 装配表
    self._render_nodes = {"minutes_generation": self._minutes_generation_render_node, ...}
    self._fallback_nodes = {"minutes_generation": self._minutes_generation_fallback_node, ...}
    self._report_assemblers = {"minutes_generation": ("minutes", MinutesReport, False), ...}
```

**① `LLMClient()` 配置解析**（`resolve_llm_settings`）：

- `DEEPSEEK_API_KEY`（.env，必填，缺失抛 ValueError）
- `DEEPSEEK_BASE_URL` → `https://api.deepseek.com`（默认）
- `DEEPSEEK_MODEL` → `deepseek-chat`（默认）
- `DEEPSEEK_TEMPERATURE` → 0（默认，追求确定性）
- 其它默认：`timeout=120s`、`max_retries=2`（指数退避 1s→2s）

**② `MeetingAgentFactory.create(client)`**：返回 dict，装配 5 个组件（核心 2 + 纪要线 3）。其中纪要 supervisor 构造时执行 `GlobalSupervisor.build_prompt(MINUTES_SUPERVISOR_DOMAIN_PROMPT)`——把全局整体标准（`GLOBAL_SUPERVISOR_PROMPT`）**注入**领域审核 prompt，拼成一份完整 system prompt（不额外发起 LLM 调用）。

## 4. `run_streaming()`：状态准备 + 图构建

```python
async def run_streaming(transcript, user, templates, lines):
    transcript = _normalize_transcript(transcript)   # 合并段落内硬换行，保留段落间空行
    objective_mode = is_objective_perspective(user)  # True
    templates = _normalize_templates(template, item_template, templates)  # 已含 minutes_generation
    initial_state = {
        "transcript": transcript,
        "user": user.model_dump(),          # 含 perspective="objective"
        "objective_perspective": True,
        "templates": {"minutes_generation": "<模板全文>"},
        "streaming": True,                  # 图内渲染节点跳过 LLM，由本方法接管流式
    }
    line_names = self._normalize_lines(["minutes_generation"])  # 二次校验
    minutes_in = True; actions_in = False
    graph = self._build_graph(["minutes_generation"])
    state = await graph.ainvoke(initial_state)   # ← 图执行（见第 5 节）
```

### 4.1 `_build_graph(["minutes_generation"])` 构图

```
StateGraph(MeetingState)
│
├─ 第一段：core（手写节点，任何任务线都要）
│   add_node("meeting_understanding", self._meeting_understanding_node)
│   add_node("perspective_modeling", self._perspective_modeling_node)
│   add_edge(START, "meeting_understanding")     ┐ 并行
│   add_edge(START, "perspective_modeling")      ┘
│
└─ 第二段：for line_name in ["minutes_generation"]（注册表驱动）
    agent_node     = self._make_agent_node("minutes_generation")
    supervisor_node= self._make_supervisor_node("minutes_generation")
    revision_node  = self._make_revision_node("minutes_generation", agent_node)
    route          = self._make_route("minutes_generation")
    add_node("minutes_generation_agent", agent_node)
    add_node("minutes_generation_supervisor", supervisor_node)
    add_node("minutes_generation_revision", revision_node)
    add_node("minutes_generation_render", self._render_nodes["minutes_generation"])
    add_node("minutes_generation_fallback", self._fallback_nodes["minutes_generation"])
    add_edge(core, "minutes_generation_agent")        # core 汇合 → agent
    add_edge("minutes_generation_agent", "minutes_generation_supervisor")
    add_conditional_edges("minutes_generation_supervisor", route, {
        "minutes_generation_render": "minutes_generation_render",      # approve
        "minutes_generation_revision": "minutes_generation_revision",  # revise
        "minutes_generation_fallback": "minutes_generation_fallback",  # reject/超限
    })
```

**注意**：`--task minutes` 时待办线节点**根本不建**（`line_names` 只有纪要），不会产生任何待办 LLM 调用。

## 5. 图执行 `graph.ainvoke(initial_state)`（核心阶段）

执行顺序由**边**决定。正常路径共 4 次 JSON 结构化 LLM 调用：

### 5.1 节点 1+2：会议理解 / 视角建模（**并行**）

| 节点 | 调用 | 产出 |
|---|---|---|
| `meeting_understanding` | `meeting_understanding_agent.run(transcript)` → `LLMClient.structured(system, user, MeetingUnderstanding, 契约)` | `state["meeting_understanding"]` |
| `perspective_modeling` | `perspective_modeling_agent.run(transcript, json(user))` → `structured(..., PerspectiveModeling, 契约)` | `state["perspective_profile"]` |

`structured()` 内部（client.py）：
1. 组装 messages：`system = 领域 prompt + "\n\n输出规则：…只输出 JSON 对象、字段与模板完全一致…\n唯一合法的输出模板：\n{契约}"`；`user = 会议原文`。
2. `json_mode=True` → 请求体带 `response_format={"type":"json_object"}`，POST `{base_url}/chat/completions`（`Authorization: Bearer {api_key}`）。
3. 响应 → `_parse_and_validate(content, 模型)`：`json.loads` + `validate_payload`（浅校验：第一层键齐全 + 类型）。
4. **校验失败** → 把错误拼回对话让 LLM 重发（最多 `max_retries=2` 次）→ 仍失败 → `SchemaRepairAgent` 修复 → 再校验 → 仍不行抛 `RuntimeError`。
5. 网络错误 → 指数退避重试（1s→2s）→ 耗尽抛错。

任一步抛错 → 节点 `except` 分支：写 `_EMPTY_MEETING_UNDERSTANDING`（或 `_EMPTY_PERSPECTIVE_MODELING`）+ `quality_degraded=True`，**不中断流程**。

### 5.2 节点 3：`minutes_generation_agent`（生成纪要草稿）

1. `_shared_context(state)` 拼上下文：视角模式 / 用户画像 JSON / 会议理解 JSON / 视角模型 JSON / **会议原文**。
2. `agent.run(context)` → `structured(..., Minutes, MINUTES_GENERATION_OUTPUT_CONTRACT)`（第 3 次 LLM 调用，`json_mode`）。
3. 成功 → `lines["minutes_generation"]["draft"] = Minutes 模型 dump`（headline / executive_summary / key_decisions / personally_relevant_points / …）。
4. 失败 → 写 `_EMPTY_MINUTES` + `degraded=True`。

### 5.3 节点 4：`minutes_generation_supervisor`（审核草稿）

1. `_supervisor_context(state, "minutes_generation")` 拼上下文：视角模式 / "纪要返工次数：0/1" / "本轮可以选择 approve、revise 或 reject" / 会议原文（最高事实来源）/ 用户画像 / 会议理解 / 视角模型 / **纪要草稿**。
2. `supervisor.review(context)` → `structured(全局注入后的 system prompt, context, MinutesSupervisorReview, 契约)`（第 4 次 LLM 调用）。
   - system prompt = `GLOBAL_SUPERVISOR_PROMPT（整体标准：忠于原文、结构完整、可读性…）` + `\n\n` + `MINUTES_SUPERVISOR_DOMAIN_PROMPT（纪要领域三维审核规则）`
3. 产出 `decision ∈ {approve, revise, reject}` + 三维检查（facts / perspective / consistency）+ `feedback`（深校验：枚举 + 语义联动——approve 不得有 failed 检查项、reject 必须至少一个 fail）。
4. 失败 → 写 `_REJECT_MINUTES_REVIEW` + `degraded=True`。

### 5.4 节点 5：条件路由 `route(state)`

```python
decision = lines["minutes_generation"]["supervisor_review"]["decision"]
if decision == "approve": return "minutes_generation_render"
if decision == "reject" or revision_count >= MAX_REVISIONS(1): return "minutes_generation_fallback"
return "minutes_generation_revision"
```

- **approve（正常路径）** → `minutes_generation_render`
- revise → `minutes_generation_revision`：**复用 agent 节点重跑**，`revision_count` +1，带上 `feedback` 重新生成 → 再审核（最多 1 次返工）
- reject / 返工超限 → `minutes_generation_fallback`（降级）

### 5.5 节点 6：`minutes_generation_render`（图内部分）

```python
if state.get("streaming"):   # ← 本命令是流式模式
    return {"lines": {"minutes_generation": {"rendered": ""}}}
```

**图内不调 LLM**，渲染交给 `run_streaming` 的流式阶段（见第 6 节）。图到此结束，`state` 返回。

> 小结：正常路径**图内共 4 次结构化 LLM 调用**（理解、视角、纪要草稿、审核），全部失败都有空壳/拒绝常量兜底，`quality_degraded=True` 标记。

## 6. 流式输出阶段（`_produce` + 事件队列）

```python
queue = asyncio.Queue()
tasks = [asyncio.create_task(self._produce("minutes_generation", state, queue))]
remaining = 1
while remaining:
    event = await queue.get()
    if event is None: remaining -= 1; continue
    if isinstance(event, Exception): raise event
    yield event                      # ← 逐个交给 bootstrap 打印
yield {"type": "done", "quality_warning": None}
```

### 6.1 `_produce("minutes_generation", state, queue)` 内部

```python
output_key, _cls, emit_items = self._report_assemblers["minutes_generation"]  # ("minutes", MinutesReport, False)
render = self.minutes_generation_render
event_type = "minutes_chunk"          # {output_key}_chunk
degraded = lines["minutes_generation"].get("degraded")  # False（正常路径）
template = templates.get("minutes_generation", "")      # ← project_progress.md 全文
```

- `emit_items=False`（纪要线不走结构化列表事件）。
- `degraded=False` → 正常分支：
  1. `context = self._minutes_generation_render_context(state, fallback=False)`：拼渲染上下文（视角模式 / 会议原文 / 用户画像 / 已审核会议理解 / 已审核用户视角 / **已批准纪要草稿** / 纪要审核结论）。
  2. `render.stream(context, template)` → `MinutesGenerationRender._prompt_and_user`：
     - 有模板 → `prompt = MINUTES_RENDER_TEMPLATE_PROMPT`，`user = context + "\n\n" + 模板全文`（**模板原样拼进 user，LLM 只替换 `[...]` 占位符，其余逐字符保留**）
     - 无模板 → `prompt = MINUTES_RENDER_PROMPT`，`user = context`
  3. `self.client.stream_text(prompt, user)`（第 5 次 LLM 调用，**流式非 JSON**）：
     - 请求体 `stream=True`，不带 `response_format`
     - 同步 SSE 读取在**后台线程**执行，chunk 经 `loop.call_soon_threadsafe(queue.put_nowait, chunk)` 桥接进 asyncio.Queue（Windows 下线程安全关键）
     - 连接失败指数退避重试；一旦产出内容中途断流不重试
  4. `async for chunk in render.stream(...)` → 每块 `queue.put({"type": "minutes_chunk", "text": chunk})`
- `finally: queue.put(None)`（结束哨兵，主循环据此 `remaining -= 1`）

### 6.2 bootstrap 消费事件（打印）

```python
elif etype == "minutes_chunk":
    if not minutes_started:
        logger.info("")
        _section("客观会议纪要")      # ← objective_mode=True 的标题
        minutes_started = True
    sys.stdout.write(event["text"]); sys.stdout.flush()
```

- 第一个 `minutes_chunk` 到达 → 打印 `── 客观会议纪要 ──` 标题 → 之后**逐块追加**，终端实时增长。
- `done` 事件：`quality_warning=None`（正常路径）→ 不打印警告。
- 收尾：`minutes_started=True` → 补一个换行。

## 7. 整条命令的 LLM 调用清单（正常路径，共 5 次）

| # | 调用方 | 模式 | 模型 | 目的 |
|---|---|---|---|---|
| 1 | `meeting_understanding` 节点 | `structured`（JSON） | `MeetingUnderstanding` | 会议理解 |
| 2 | `perspective_modeling` 节点 | `structured`（JSON） | `PerspectiveModeling` | 视角建模 |
| 3 | `minutes_generation_agent` | `structured`（JSON） | `Minutes` | 纪要草稿 |
| 4 | `minutes_generation_supervisor` | `structured`（JSON） | `MinutesSupervisorReview` | 三维审核 |
| 5 | `_produce → render.stream` | `stream_text`（SSE 流） | — | 按模板流式渲染纪要正文 |

每次 `structured` 内部最多 2 次校验重发 + 1 次 SchemaRepair，网络错误最多 2 次指数退避重试；`stream_text` 连接阶段同。全部兜底层层递进（见第 8 节）。

## 8. 兜底体系（本次命令中可能触发的降级路径）

| 层 | 触发条件 | 行为 |
|---|---|---|
| 网络重试 | API 连接失败/超时/限流 | 指数退避 1s→2s 重发（`max_retries=2`） |
| 校验重试 | 输出不符合契约 | 错误拼回对话让 LLM 重发（≤2 次） |
| SchemaRepair | 校验重试耗尽 | 独立 agent 修复 JSON（+1 次调用） |
| 节点 except | 某节点仍抛错 | 写 `_EMPTY_*` / `_REJECT_*` 常量 + `degraded=True`，继续跑 |
| 路由降级 | reject / 返工超限 | 进 `_fallback_node`：降级渲染（流式模式直接标记 degraded，不调 LLM） |
| 图外层 | 图整体异常 | 确定性拼装 Report + `quality_warning` |
| 输出校验 | 最终 Report 校验失败 | 退回确定性兜底 Report |
| 事件异常 | 生产者抛错 | 异常对象经队列抛出给调用方 |

本次正常路径**不会**触发任何降级，`done.quality_warning=None`。

## 10. 关键设计点回顾

1. **`--task minutes` 为什么只跑纪要**：`_normalize_tasks` 把友好名翻成线名 → `_build_graph` 只给选中的线建节点 → 未选中的线**零 LLM 调用、零事件**。
2. **模板如何生效**：`--minutes_template` 读文件 → `templates["minutes_generation"]` → 渲染时 `user = 上下文 + "\n\n" + 模板全文`，LLM 只填 `[...]` 占位符，其余逐字符保留（`MINUTES_RENDER_TEMPLATE_PROMPT` 约束）。
3. **客观模式怎么来的**：`object_profile.json` 的 `perspective=objective` → `is_objective_perspective=True` → 视角上下文、终端标题、agent prompt 全部走客观口径。
4. **流式怎么实现的**：SSE 流在后台线程读 → `call_soon_threadsafe` 桥接进 asyncio.Queue → `_produce` 逐块塞事件队列 → `run_streaming` 主循环 yield → bootstrap `sys.stdout.write` 实时打印。
5. **5 次 LLM 调用**是"理解→视角→草稿→审核→渲染"五段流水，审核通过才渲染；任何一段失败都有兜底，不会让整条命令崩溃。
