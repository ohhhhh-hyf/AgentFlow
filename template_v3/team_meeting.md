# [例会概况]
[一段话概括本次例会（约 250–400 字，信息多就拆成两段）：① 参会成员或部门（姓名优先，没人名写部门/角色，人数照原文）② **为什么开这次会**（当前阶段或由头，原文有才写）③ 主线议题（把议题名列出来，**每块用一句话交代谈到什么程度：已定 / 待定 / 仅同步**，不展开任务明细）④ **整体态势**（哪些顺利、哪些卡住或延期、是否按计划，一两句）⑤ 结论与下一步方向（没有结论就写「本次以同步为主，未形成明确结论」）⑥ **1–3 个关键数字或时间节点**（人数、任务数、节点日期、延期天数，一条都没有＝不合格）；各任务的进展与分工明细归 [工作进展]（谁做了什么、做到什么程度、下一步与时限）、需要别人配合的事归 [协作需求]，**本栏只到「议题级主线 + 态势」，不写任务级明细**；内容够就写到接近 400 字——低于 250 字说明没交代清「为什么开、谈成什么样、态势如何」]

# [工作进展]
[按成员或任务维度分级呈现（二级标题 `##` 写成员或模块，下方用 `- ` 列任务要点），**每条写成 `- **任务名**：进展；下一步…；时间节点…`**——四要素（谁、做了什么、做到什么程度、下一步）齐全，信息少的也要写清进展，**不要只写状态或半句碎片、不要一句一条**（同一次修改的连续动作合并成一条）；**同一模块/成员下并列的多个任务各占一条，不要压成一条；一个任务讲不完就用缩进子条 `  - ` 拆开；原文提到的具体任务、数字、时间节点都要落进对应条目**；状态（✅已完成 / 🔄进行中 / ⛔阻塞）在任务名后标一次；关键阻塞、延期节点与任务名、版本号、工单号各用 **具体内容** / `具体内容` 标注]

# [协作需求]
[列出成员间提出的协作请求、跨人/跨组依赖项及需要支持的事项，写清提出方与配合方；**只写需要别人配合的事（谁需要谁做什么、何时前），已在 [工作进展] 写过的进展不复述**；原文提到的跨人依赖一条不落；同一任务沿用[工作进展]里的名称，不要换称]
