## [研讨背景与议题]
[上半段一段话交代研讨背景：主题、参与方（人数/机构/方向照原文；**原文没说参与方就不写**）、为什么开这场研讨；下半段最顶层级按数字序号（1. 2. 3. ...）一行一项逐条列出（`1. **议题名**：要解决的核心痛点 / 待解问题 / 为什么重要`，亦兼容 `- **议题名**：要解决的核心痛点 / 待解问题 / 为什么重要`），议题名取原文说法，一条一个议题，宁多不漏；人员与数字照原文；【板块列举纪律】下半段列出的议题清单为正文核心范围，下文 [核心观点] 设立的小节（###）必须 100% 逐一对应落地展开，严禁前文列出后文中途截断或大面积遗漏！]

## [核心观点]
[【防大篇幅与单点遗漏】必须以研讨背景列出的全部核心议题为底账，逐一设立对应小节（### 议题名）展开，严禁中途遗漏任何议题！每个议题下必须有充分事实支撑；推行高密度微语法，用“观点提炼+事实依据/数据+提出方”紧凑表述，严禁过程铺陈与空话套话；同一议题下的多重视角用分号并列打包，严禁为控长而粗暴删减关键观点；按议题维度梳理（每个主要议题一行 `### 议题名` 展开，亦兼容按数字序号集中列出）：最顶层级按数字序号（1. 2. 3. ...）一行一项列出不同视角的观点、提出的创新思路、数据或案例支撑（格式：`1. **观点提炼短语**：具体主张与论据（提出方/发言者照原文）`，亦兼容 `- **观点提炼短语**：…`；**每条以该观点的核心关键词/论题加粗起头，禁止机械使用「倾向性认识」「核心观点」等套话作前缀**）；对立观点分别标注提出方]

## [达成共识与解决方案]
[【防结论与待办遗漏】全面打捞并汇聚研讨形成的全部共识与解决方案，确保关键结论 100% 沉淀；有共识就写共识：谁与谁一致、依据是什么；**未形成统一结论时直写「未形成统一结论」，再分条提炼本场研讨形成的倾向性认识与主流意见**（每条以具体的共识/结论主题词加粗开头：`1. **结论主题**：具体认识与依据…` 或 `- **结论主题**：…`；**严禁机械重复「倾向性认识」「主流意见」等空洞套话作为加粗前缀**，不要用无倾向的观点散漫罗列充当共识）；解决方案最顶层级按数字序号（1. 2. 3. ...）一行一项写成可落地条目：对象 + 做法 + 依据/前提，原文没有就写「未提及」（不写说明句）；关键结论用**加粗**]

## [未决分歧与后续探索]
[【防结论与待办遗漏】全面打捞所有分歧验证事项与口头跟进承诺，确保探索待办 100% 沉淀，绝不遗漏隐性承诺；最顶层级按交互复选框（- [ ] ）或数字序号（1. 2. 3. ...）一行一项列出，每条写清：分歧点是什么 + 双方各自主张（标注提出方）+ 需要验证什么 / 谁跟进（原文有才写，格式推荐：- [ ] **探索事项**（跟进人 ｜ 验证目标 ｜ 下阶段计划））；**只写原文说出具体事项与责任方或跟进人的内容**；整条确实无信息就**不写该条**（不要逐条标「未明确」）；整栏都没有内容时才用一次「未明确」；【属性刚性纪律】括号内（跟进人 ｜ 验证目标 ｜ 下阶段计划）仅记录原文明确提及的要素；原文未提及的要素直接省略，缺项即止，严禁脑补补全！]
