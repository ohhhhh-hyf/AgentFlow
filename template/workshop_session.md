# 工作研讨会

## [研讨背景与议题]
[上半段一段话交代研讨背景：主题、参与方(人数/机构/方向照原文；**原文没说参与方就不写**)、为什么开这场研讨；下半段最顶层级按数字序号(1. 2. 3. ...)或列表符(`- `)一行一项逐条列出(`1. **议题名**：要解决的核心痛点 / 待解问题 / 为什么重要`，亦兼容 `- **议题名**：要解决的核心痛点 / 待解问题 / 为什么重要`)，议题名取原文说法，一条一个议题，宁多不漏；人员与数字照原文]

## [核心观点]
[按议题维度逐一设立小节(`### 议题名`)，其下最顶层级按数字序号(1. 2. 3. ...)或列表符(`- `)一行一项列出不同视角的观点、提出的创新思路、数据或案例支撑(`1. **观点提炼短语**：具体主张与论据(提出方)`；每条以具象的业务议题或方案词加粗引领；**标题下必须至少一条正文(`- ` 条目或一段)，不得只有标题；写不出内容的不立标题**)。对立观点分别标注提出方，数据或案例支撑照原文写实]

## [达成共识与解决方案]
[有共识就写共识：每条以具体的结论主题词加粗开头(`1. **结论主题**：谁与谁一致、依据是什么`；亦兼容 `- `)，**未形成统一结论时直写「未形成统一结论」，再写本场的倾向性认识与主流意见**(不要用观点罗列充当共识)；解决方案最顶层级按数字序号(1. 2. 3. ...)或列表符(`- `)一行一项写成可落地条目：对象 + 做法 + 依据/前提，原文没有就写「未提及」(不写说明句)；关键结论用**加粗**]

## [未决分歧与后续探索]
[(观点碰撞与探索路径全景记录)优先按列表清单 `- **探索事项/分歧焦点**(跟进人 ｜ 验证目标 ｜ 下阶段计划)` 一行一项列出(亦兼容按数字序号 1. 2. 3. ... 一行一项)，每条完整展开因果事实要素：分歧症结 ➔ 双方各自主张与支撑论据(保留分歧双方的对立观点，标注提出方)+ 后续验证目标与约束条件 + 跟进责任人与阶段推进计划(原文有才写)；主干条目定调探索焦点，次级展开(2 空格 `  - `)交代双方论据细节与测试目标；**只写原文说出具体事项与责任方或跟进人的内容**；整条确实无信息就不写该条(不要逐条标「未明确」)；整栏都没有内容时才用一次「未明确」]
