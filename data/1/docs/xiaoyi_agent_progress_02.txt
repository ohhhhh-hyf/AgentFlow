会议主题：小艺慧记Agent开发进展内测前推进会
会议时间：2026年8月18日 15:00-16:10
参会人员：产品负责人周宁、算法负责人林夏、后端负责人赵衡、前端负责人钱屿、测试负责人陈澄、运营顾问许安

周宁：今天继续跟进「小艺慧记Agent开发进展」。上次会议已经确认，内测前要重点收口 minutes_trace、记忆引用可解释性、Gradio界面配置和测试样例。今天不重新讨论项目定位，只看这几项有没有推进，以及还有哪些会挡住8月下旬内测。

林夏：minutes_trace 这几天做了两轮优化。第一，场景模板不再依赖用户自定义上传，而是先做会议场景匹配，匹配不到就走通用兜底模板。这样输出结构更稳定，不会因为用户随便贴一个模板导致纪要变形。第二，prompt 里加强了“会议结论、风险阻塞、行动项都可以溯源”的要求，用户关键点和笔记允许多次被引用。我们用上次那组销售复盘会议测试，原来只保留14个有效钉，现在可以挂到更多段落，尤其是会议风险和结论部分有改善。不过仍有一个问题：如果用户笔记是情绪化批注，模型有时会把批注原样带得太重，需要再控制语气。

赵衡：记忆引用这块已经改了展示方式。上次大家觉得“记忆1、记忆2”太像内部脚注，这次改成正文中被历史记忆影响的内容直接加下划线，点击后跳到底部来源。底部会展示“来自哪次历史会议、时间、类型、关联对象和历史片段”。比如本场如果提到 Gradio 模板入口移除，系统可以指向上次会议里钱屿负责8月20日前移除 minutes_trace 模板入口的结论。技术上新增了来源索引，不进入正文，只给引用器使用。现在还需要观察 Markdown 预览里 HTML 下划线链接的显示是否符合用户习惯。

钱屿：Gradio界面已经同步改完。切到 minutes_trace 时，渲染模板区会隐藏，溯源材料区只保留用户关键点和用户笔记，不再出现“纪要骨架模板”。我也处理了任务切换时的旧模板状态，避免用户从其他任务切回 minutes_trace 后按钮还显示“确认模板并运行”。上传文件控件高度也已经拉高，字体不会再被挡住。剩下的问题是结果预览里的下划线样式还比较朴素，如果要给内测用户看，可以再加一点 hover 提示，比如鼠标放上去显示“查看历史会议来源”。

陈澄：测试侧今天跑了三组前后会议。第一组是“小艺慧记Agent开发进展”，第二场确实能识别出前一次会议已经完成任务目录整理、Gradio基础界面、minutes_trace 初版和会议记忆写回。第二组是销售复盘会议，记忆能接住上次遗留的客户审核风险，但有一条历史风险被过度关联到了行动项里。第三组是笔记知识图谱，notes 的 graph 仍能按用户和学科增量合并，没有被会议记忆改动影响。建议内测前再做一次回归，重点看 memory 引用是否会误标普通事实。

许安：从运营和内测说明角度，我建议不要在页面上使用“memory”或“历史项目记忆”这种词，可以叫“历史会议来源”或“参考过的历史会议”。用户看到下划线会知道这里可以点，点进去看到会议名称和时间就足够了。底部来源也不要太长，最好每条控制在两三行。否则一份会议纪要下面堆太多来源，会显得很吓人。

周宁：结论如下。第一，minutes_trace 不再支持用户自定义模板，这个方向确认，后续只走场景匹配和通用兜底模板。第二，记忆引用默认采用正文下划线加底部历史会议来源的方式，文案尽量改成用户能理解的“来自历史会议”，不要暴露“记忆1”这类编号。第三，Gradio界面目前可以进入内测候选，但下划线 hover 提示和底部来源文案还要再打磨。第四，测试侧8月20日前完成三类回归：会议纪要记忆、溯源纪要、笔记知识图谱。

行动项方面，林夏在8月19日前继续调整 minutes_trace 对情绪化用户批注的处理，保留事实价值但不把情绪词写进正式纪要。赵衡在8月19日前把底部“历史记忆引用”的标题改成更用户化的“参考的历史会议”，并限制每条来源展示长度。钱屿在8月20日前给下划线来源加 hover 提示，并确认 Gradio Markdown 预览和下载后的 Markdown 都能正常点击。陈澄在8月20日前完成回归报告，标出是否还有误引用、漏引用和结构不稳定问题。

风险方面，目前内测主要风险从“功能不可用”转为“用户是否理解并信任”。如果下划线标记太多，用户可能觉得正文被打扰；如果标记太少，又看不出历史记忆的价值。未决事项是：内测版是否把历史会议来源默认展开，还是默认收起只在点击后查看。
