# 小艺慧记Agent第一阶段复盘与内测收口
本次会议复盘「小艺慧记Agent开发进展」第一阶段情况，确认8月下旬内测前必须收口的事项。当前整体进度约完成60%，会议纪要、待办提取、风险分析、思维导图几条主线已能跑通，Gradio测试界面支持上传会议文本、选择任务并预览结果；用户最关心的是生成内容是否稳定、结构是否清楚、能否解释为什么这么写。算法侧会议理解和纪要生成主流程稳定，基础事实抽取比上周好很多，但会议模板匹配不够准（销售复盘会被识别成普通项目周会），用户笔记和关键点溯源不充分（模型有时只挂十几条证据），已新增 minutes_trace 任务把用户笔记和关键点尽量挂到对应段落，仍需优化对齐策略。
后端已整理任务目录，meeting 和 notes 公共运行逻辑归到 tools 层，memory 只在 meeting 的 minutes、minutes_styles 及 notes 的 graph 上启用，会议记忆写回可记录项目目的、议题、决策、风险、未决项和场次快照，首次会议不传 project 自动生成 p1，传「小艺慧记Agent开发进展」则按该项目写入，后续会议先用 project_key 和显式项目名匹配再用实体重叠弱匹配。前端本周修复上传控件高度不够、字体被挡住问题，去掉 minutes_trace 自定义模板入口，溯源材料区只保留用户关键点和用户笔记，并建议记忆引用不用「记忆1、记忆2」工程化标记，改为对用到历史记忆的内容加下划线、点击展开来源。测试侧提出内测前三类问题：minutes_trace 在复杂会议中可能把会议结论写散，风险、阻塞和行动项边界不够清晰；记忆引用虽能出现但用户看不出自哪一次会议；部分输出仍有「记忆命中显示」这类系统表达不够自然，建议把记忆来源展示放到底部，显示历史会议名称、时间、类型和原片段。交付视角指出内测用户会用真实会议资料、不理解内部 task 名称，最看重结构稳定、证据可信、历史进展能接上，例如今天这场会写入记忆后，下一场再讲「小艺慧记Agent开发进展」应知道之前已完成任务目录整理、Gradio基础界面、minutes_trace 初版和会议记忆写回，而不是当成新项目。
会议形成四项收口安排：8月18日前林夏继续优化 minutes_trace 的场景匹配、模板输出要求和证据对齐策略，目标是用户关键点和笔记在不捏造事实的前提下尽可能挂上；8月19日前赵衡补齐记忆引用的来源字段，包括历史会议时间、会议名称、类型和关联对象；8月20日前钱屿把 Gradio 界面中 minutes_trace 的模板入口彻底移除并保留关键点、笔记上传入口；8月21日前陈澄准备一组前后两场会议的记忆测试样例，重点验证第二场是否能接住第一场的项目进展。
风险方面，记忆能力已可用但可解释性还不够像用户产品，用户看不到「用了哪次历史会议」会误以为系统凭空补充，minutes_trace 证据挂载太少会削弱用户对溯源纪要的信任。未决事项是：是否在内测版默认开启记忆引用下划线展示，还是先作为实验开关提供。
