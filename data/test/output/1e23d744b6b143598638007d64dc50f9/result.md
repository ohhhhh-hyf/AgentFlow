# 全文摘要
本次会议为手机图库项目团队例会，由主持人（产品经理）召集，产品、开发1、开发2共四人参与，围绕项目整体进展、排期与潜在风险进行对齐。会议覆盖智能分类与相册推荐改版、AI智能标签接口与模型部署、云同步模块断点续传与OOM问题、缩略图渲染优化、时间轴视图加载速度、AI修图入口预留及项目排期等板块。关键结论包括：隐私相册入口上提至首部顶部二级菜单；AI标签接口采用本地缓存策略并增加端侧预过滤；云同步采用分片加载方案；缩略图渲染优化采用新解码库，数据库锁死Bug临时规避、正式修复排入V1.2迭代；时间轴视图加本地索引预加载；AI修图本次不硬塞，预留接口与插件化架构；里程碑按原定计划月底封版，内测包暂定下周三发布。关键数字锚点：AI识别准确率较上代提升约88%，单次请求耗时从800毫秒涨至约1.5秒，内存占用降约30%，端侧预过滤需申请200MB本地缓存空间。

# 要点梳理
## 智能分类与相册推荐改版

1. 高保真原型已出V1.5版，调整网格视图交互逻辑，长按手势增加微动效反馈。
2. 低端机上滑列表偶发掉帧，已与开发2沟通，拟通过降低预览图缩放级别换帧。
3. 用户调研反馈隐私相册入口太深，产品建议下一版提到首部顶部二级菜单。
4. 产品经理确认入口改动不算大，要求产品出交互方案供评审。

## AI智能标签接口与模型部署

1. 后端V2版识别模型已跑通，准确率较上一代提升约88%。
2. 因新增视频帧提取功能，单次请求耗时从800毫秒涨至约1.5秒。
3. 异步推送方案被否决，改为本地缓存策略：首次识别慢、之后本地读库秒出；开发1下午拉分支改逻辑，预计三天联调完。
4. 端侧预过滤方案通过：先用轻量级模型过滤gif或截图，再走全量云端识别，平均耗时压一半；开发1评估模型体积和端侧推理开销，需申请200MB本地缓存空间。
5. 按需加载方案通过，用现有资源下发模块实现，约两天搞定。

## 云同步模块断点续传与OOM问题

1. 云相册同步模块断点续传在弱网环境下出现状态机紊乱。
2. 同步队列积压超一千张时部分机型OOM崩溃，尤其iOS内存回收机制较激进。
3. 开发2已加分片加载机制，每次拉五十张、处理完再拉下一批，但拖慢同步进度。
4. 后台静默同步权限申请被否决（审核较严），产品经理同意分片加载方案但要求进度不能拖。

## 缩略图渲染优化

1. 采用新图片解码库，JPEG硬解换软解，内存占用降约30%，CPU占用上升。
2. 已在主流三款机型灰度，帧率稳定60帧，低端机约50帧；周四性能报告今晚出初稿。
3. 批量删除照片时若同时触发回收站重建索引，数据库偶发锁死；已写临时规避方案（消息队列排队处理），正式修复排进V1.2迭代。

## 时间轴视图加载优化

1. 滑动到二十年前老照片时页面卡死三秒以上，测试提了三个优高优Bug；根因是历史图片EXIF解析耗时加磁盘IO瓶颈。
2. 方案为本地索引预加载：最近三个月照片建树状结构，滑到底部动态加载旧数据；产品经理同意，但提醒勿与云同步模块抢资源。
3. 预加载放主线程IO池、同步放子线程后台服务，互不影响。
4. 预加载需用户授权媒体和存储权限，产品出引导弹窗设计（柔和提示路线，不用强制遮罩）。

## AI修图快捷入口预留

1. 运营反馈希望下版本加AI修图快捷入口（一键去背景、智能调色），本次主线为性能和分类，硬塞风险大，决定不纳入本次迭代。
2. 产品在PRD预留接口逻辑和UI占位，开发侧做插件化架构，下次迭代直接接入。
3. 开发2提出趁重构理顺图片处理管线，渲染层抽成插件化、用GLSL写统一接口，工作量多一周。
4. 产品经理同意调整优先级：非核心UI微调往后排，资源给到管线重构和AI标签优化。

## 项目排期与里程碑

1. 里程碑按原定计划月底封版，内测包暂定下周三发，拉体验官群重点跑AI分类和同步模块。
