# ASR模型迭代与线上稳定性优化例会

## 全文摘要
本次例会由组长主持，A与B两位成员参与，围绕ASR模型迭代进度、线上推理延迟及长音频解码卡死问题展开同步与协调。会议覆盖数据清洗与模型训练、推理侧动态Batching优化、长序列解码稳定性、监控系统建设及前端采样率升级等板块。关键结论包括：确认采用流式RNN-T与Transformer混合架构并先在20小时核心数据上训练；推理侧改为静态分段加流式解码方案，音频按2秒切块；针对解码卡死增加early stopping机制，稳定性优先，下周先出热修复版本上灰度；同时推进监控面板接入与CI自动评估流水线落地。关键数字锚点：有效语音时长占比提升至94%、验证集WER下降0.8个点、首字延迟目标控制在80ms以内、吞吐量稳定在120路并发、组长协调下周一划拨三块A100用于增量训练。

## 要点梳理
### 数据清洗与模型训练进展
1. 数据清洗流水线第二轮完成，长尾噪音、极端口音和背景人声重叠片段单独分流，有效语音时长占比从89%提升至94%。
2. 重新校对CTC的blank token分布，发现多音字和连读场景切分点偏移，计划用新基准跑一轮消融。
3. 验证集WER下降0.8个点；低资源语言混合边界场景下，中英文切换时模型易吞音或重复解码。
4. 计划将全纯Transformer架构换成流式RNN-T和Transformer混合形态，先在20小时核心数据上训练。
5. 数据增强策略增加时间偏移，但对背景白噪声和混响鲁棒性不足，准备引入MixUp和Cut再迭代一轮。

### 推理延迟与动态Batching优化
1. 动态Batching在长短音频混排时导致首字延迟波动在150ms至300ms之间，产品反馈体验不连贯。
2. 确认改为静态分段加流式解码组合方案：音频按2秒切块，前端VAD预过滤，后端RNN-T增量解码；目标首字延迟控制在80ms以内，整体吞吐量稳定在120路并发。
3. VAD预过滤阈值暂定-25dB，结合能量和谱熵双模型判断；组长要求B做消融实验，画误切率和漏切率曲线找最优解。
4. 组长要求流式架构切换不影响非流式离线批处理，双线都要保，测试用例需覆盖全。
5. 组长协调下周一划拨三块A100做增量训练，需与NLP组错峰使用；A调整启动脚本，优先跑验证集小的实验，大训练放周末夜间。
6. RNN-T的prefix LM缓存拟做INT8量化，配合动态缓存释放策略，预计压降30%显存占用；压测日志和截图明天下午发群。

### 长音频解码卡死问题
1. 线上超长连续且带方言口音的音频导致解码器陷入无效循环，服务器节点重启；根因是RNN-T的attention权重震荡未收敛。
2. 解码器默认max steps为2048个token，超时时间5秒；实际序列长度超限时未做优雅降级，直接报OOM。
3. 确认增加early stopping机制：连续30步置信度低于0.2时强制截断并返回当前序列，预计解决90%以上卡死问题；同时完善超时熔断和降级返回。
4. 组长定调稳定性优先、精度次之，下周先出热修复版本上灰度；专业术语后续通过词表扩展和热词注入解决。
5. A负责长序列数据配比和边界用例验证，避免训练数据全塞短音频。

### 监控系统与CI自动评估
1. 现有日志系统简陋，线上推理中间特征和中间帧无法落盘，排查问题全靠猜。
2. 确认接入Prometheus和Grafana监控面板，可视化QPS、延迟、显存利用率、解码步数、VAD误切率。
3. 告警阈值分两级：P0为服务不可用或延迟超500ms，P1为显存超85%或WER突增。
4. A负责用GitLab CI搭建自动评估流水线：代码合入即触发数据拉取、模型加载、测试集解码、结果对比，WER未下降或RTF超标直接打回；预计三天落地，周四前出V1版本。
5. B配合将压测数据输出为标准JSON格式，供流水线直接读取。

### 前端32k采样率升级
1. 前端SDK音频采样率仍为16k，新模型为32k输入；不升级则上采样引入高频伪影，影响识别率。
2. 32k模型在长尾词上WER比16k好0.5%；前端排期推至下个月，组长计划拉产品和技术总监优先插队。
3. B先写轻量级重采样插件（libresample），实测CPU占用和延迟影响，CPU开销控制在5%以内再提方案；服务端加模块会增加推理链路延迟，需对比后决策。

### 结论与决定
1. 确认采用流式RNN-T和Transformer混合架构，先在20小时核心数据上训练。
2. 确认推理侧采用静态分段加流式解码方案，音频按2秒切块，前端VAD预过滤。
3. 长序列解码卡死问题：增加early stopping机制和超时熔断，稳定性优先，下周先出热修复版本上灰度。
4. 确认接入Prometheus和Grafana监控面板，告警分P0/P1两级。
5. 前端32k采样率升级需推动，B出对比文档和重采样插件实测后决策。
