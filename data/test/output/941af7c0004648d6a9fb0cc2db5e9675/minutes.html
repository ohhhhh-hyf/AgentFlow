手机图库项目进展对齐与排期风险评审会

全文摘要

本次例会由主持人召集，产品经理、开发1、开发2参会，围绕手机图库项目进展、排期与风险对齐。会议覆盖智能分类与相册推荐改版、AI智能标签接口与模型部署、云同步模块断点续传与OOM问题、缩略图渲染卡顿优化、时间轴视图加载速度优化、AI修图功能预留、项目里程碑与内测计划等板块。关键结论包括：隐私相册入口提升至首部顶部二级菜单；AI标签采用本地缓存策略；云同步采用分片加载方案；缩略图渲染临时规避方案先稳住，正式修复排进V1.2迭代；时间轴加载采用本地索引预加载；AI修图功能本次不实现，预留接口和插件化架构；里程碑按原定计划月底封版，内测包暂定下周三发。关键数字锚点：AI标签V2识别模型准确率提升约88%，单次请求耗时从800毫秒增至约1.5秒；缩略图渲染内存占用降约30%，主流机型灰度帧率稳定60帧；同步队列积压超一千张时部分机型OOM崩溃。

分段速览

00:00:00–00:01:23 开场与产品侧改版进展

主持人开场说明会议目的为对齐图库项目进展、排期与风险。产品侧同步智能分类与相册推荐改版进展：高保真原型已出V1.5版，调整网格视图交互逻辑；测试反馈低端机上滑列表偶发掉帧，计划通过降低预览图缩放级别优化。用户调研反馈隐私相册入口太深，建议提升至首部顶部二级菜单，主持人确认改动不大、要求出交互方案评审，并强调掉帧问题需在性能压测前解决。

00:01:51–00:02:47 AI智能标签接口与本地缓存方案

开发1汇报V2识别模型已跑通，准确率较上代提升约88%，但因新增视频帧提取功能，单次请求耗时从800毫秒增至约1.5秒。产品否决异步推送方案，提出本地缓存策略（首次识别慢、之后本地读库秒出），开发1确认可行，计划下午拉分支改逻辑、预计三天联调完，并提示缓存命中率低时需回溯。

00:03:19–00:04:17 云同步OOM与缩略图渲染优化

开发1提出弱网环境下断点续传状态机紊乱；开发2确认同步队列积压超一千张时部分机型OOM崩溃，已采用分片加载机制（每次拉五十张），但拖慢同步进度。后台静默同步权限审核严、大概率下不了，主持人决定先按分片加载方案走、进度不能拖。开发2另汇报缩略图渲染优化：JPEG硬解换软解后内存占用降约30%、CPU上升，主流三款机型灰度帧率稳定60帧、低端机约50帧；批量删除时数据库偶发锁死，已用消息队列排队临时规避，正式修复排进V1.2迭代。

00:05:03–00:06:13 端侧预过滤与按需下载方案

主持人提出端侧轻量级预过滤思路（先过滤非图片内容、再走全量云端识别，可平均压耗时一半）。开发1评估模型体积与端侧推理开销，需再申请两百兆本地缓存空间；产品确认安装包增加两三百兆问题不大，建议做成按需加载（首次进智能标签时才触发下载），开发1确认用现有资源下发模块即可、约两天搞定。

00:07:01–00:07:48 时间轴加载优化与权限引导

开发1报告时间轴滑动到二十年前老照片时卡死三秒以上，根因是EXIF解析耗时与磁盘IO瓶颈，计划加本地索引预加载（最近三个月照片建树状结构、滑到底部动态加载旧数据）。开发2确认预加载放主线程IO池、同步放子线程后台服务，互不冲突；预加载需用户授权媒体与存储权限，引导弹窗由产品明天出稿，走柔和提示路线。

00:08:16–00:09:42 AI修图预留与渲染管线重构

运营反馈希望下版本加AI修图快捷入口（一键去背景、智能调色等），主持人决定本次不实现，在PRD预留接口逻辑与UI占位、开发侧做插件化架构。开发2提出当前图片处理管线耦合深，建议趁重构抽成插件化、用GLSL写统一接口，工作量约多一周，需将非核心Bug修复后移腾出资源，主持人同意调整优先级并要求今天下班前评估精确工作量。

00:10:19–00:12:18 里程碑、内测计划与收尾分工

产品确认里程碑按原定计划月底封版，内测包暂定下周三发，重点跑AI分类和同步模块，产品准备反馈收集表、开发准备日志抓取。开发1今晚搭接口联调环境、明天与测试过一遍，并拉群与DBA对齐索引策略；开发2今晚继续跑压测数据、明天同步，并让测试组将iOS与安卓对比数据合并成一份总览报告。主持人下午两点参加UI走查，周四性能压测由测试部配合、需拿到达标数据。

要点梳理

智能分类与相册推荐改版

  1. 高保真原型已出V1.5版，调整了网格视图交互逻辑，长按手势增加微动效反馈。
  2. 测试反馈部分低端机上滑列表偶发掉帧，已与开发2沟通，考虑通过降低预览图缩放级别换取帧率。
  3. 用户调研反馈“隐私相册”入口太深，产品建议提升至首部顶部二级菜单；主持人确认改动不大，要求产品出交互方案评审。
  4. 掉帧问题需在周四性能压测前解决。

AI智能标签接口与模型部署

  1. 后端V2识别模型已跑通，准确率较上一代提升约88%。
  2. 新增视频帧提取功能后，单次请求耗时从800毫秒增至约1.5秒。
  3. 异步推送方案被否（产品认为用户点开相册无实时结果会感觉功能卡死），改为本地缓存策略：首次识别较慢，之后本地读库秒出；开发1下午拉分支改逻辑，预计三天联调完。
  4. 缓存命中率低时仍需回溯，产品需有心理预期。
  5. 端侧预过滤方案获认可：先用轻量级模型过滤非图片内容（gif、截图），再走全量云端识别，可平均压耗时一半；开发1评估模型体积与端侧推理开销，端侧运行需再申请约200兆本地缓存空间。
  6. 安装包增加两三百兆问题不大，但需做成按需加载——用户首次进入智能标签时才触发下载；开发1确认用现有资源下发模块即可，预计两天搞定，并拉开发2配合端侧推理联调。

云同步模块断点续传与OOM问题

  1. 弱网环境下断点续传状态机紊乱，开发1与开发2均确认存在类似问题。
  2. 同步队列积压至一千张以上时，部分机型出现OOM崩溃，iOS内存回收机制较激进。
  3. 开发2已采用分片加载机制，每次只拉五十张，处理完再拉下一批；但会拖慢整体同步进度。
  4. 后台静默同步权限申请审核较严，大概率下不了；确认先按分片加载方案走，但进度不能拖。

缩略图渲染卡顿优化

  1. 采用新图片解码库，JPEG硬解换软解，内存占用降约30%，CPU占用上升。
  2. 已在主流三款机型灰度，帧率稳定60帧，低端机约50帧；周四性能报告初稿今晚出。
  3. 批量删除照片同时触发回收站重建索引时，数据库偶发锁死；临时规避方案用消息队列排队处理，正式修复排进V1.2迭代。

时间轴视图加载速度优化

  1. 滑动到二十年前老照片时页面卡死三秒以上，测试提了三个优高优Bug。
  2. 根因是历史图片EXIF解析耗时太长加磁盘IO瓶颈；计划加本地索引预加载，最近三个月照片建树状结构，滑到底部再动态加载旧数据。
  3. 预加载放主线程IO池、同步放子线程后台服务，与云同步模块不冲突。
  4. 预加载需用户授权“媒体”和“存储”权限，首次拒绝需引导弹窗；产品明天出稿，走柔和提示路线，不用强制遮罩。

AI修图功能预留

  1. 运营反馈希望下版本加“AI修图”快捷入口（一键去背景、智能调色），本次主线为性能和分类，硬塞风险大。
  2. 决定本次不实现：产品在PRD中先写接口逻辑和UI占位，开发侧将模块抽象为插件化架构，下次迭代直接接入。
  3. 后端接口做成标准RESTful加Swagger文档；端侧需重构图片处理管线，渲染层抽成插件化、用GLSL写统一接口，工作量多约一周。
  4. 主持人调整优先级：非核心UI微调后移，资源给到管线重构和AI标签优化；开发2今天下班前评估精确工作量并上报。

项目里程碑与内测计划

  1. 里程碑按原定计划，月底封版；内测包暂定下周三发。
  2. 内测拉体验官群，重点跑AI分类和同步模块；产品准备反馈收集表，开发准备日志抓取。
  3. 周四性能压测由测试部配合，需拿达标数据，否则下周过评审过不去。
  4. 周四性能报告将iOS和安卓对比数据分开列，由测试组合并成一份总览。

结论与决定

  1. 隐私相册入口提升至首部顶部二级菜单，产品出交互方案评审。
  2. AI标签采用本地缓存策略，开发1下午拉分支改逻辑，预计三天联调完。
  3. 云同步采用分片加载方案（每次拉五十张），进度不能拖。
  4. 缩略图渲染优化采用新解码库，临时规避方案先稳住，正式修复排进V1.2迭代。
  5. 时间轴加载采用本地索引预加载，注意与云同步模块资源隔离。
  6. AI修图功能本次不实现，预留接口和插件化架构。
  7. 渲染管线重构纳入本次迭代，非核心UI微调后移。
  8. 里程碑按原定计划月底封版，内测包暂定下周三发。
